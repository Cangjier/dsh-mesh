# Step 040 成员详情内联修复手机端触摸即退出

手机上的会话右侧面板是一个浮层。DSH 的浮层关闭逻辑（`dsh-client-ui-session-panel` 的
`useOverlayDismissal`）在 `document` 上监听 `pointerdown`：按下的目标不在面板里、也不是打开
面板的按钮或菜单时，浮层立即关闭。这是浮层的正常行为，问题出在「成员详情」用了 antd
`Modal`——它被 portal 到 `document.body`，在 DOM 上不属于面板。于是手指刚落到详情上准备往下
滚，`pointerdown` 的目标就是「面板外」，浮层连同详情一起被关掉。

## 行为

点击成员行不再打开对话框，而是**在「成员」区内部换成详情**：

- 详情顶部一行：`← 返回列表` 和 `刷新`（重新读一次成员会话状态）；
- 下面是原来的全部字段（标准身份、身份、工作区、所属成员、工作范围、状态、轮次、会话 id、
  压缩阈值、备注、最近更新、最近任务）；
- 详情就是面板的一部分，手指落在详情里仍是「面板内」，滚动由面板自己的滚动容器完成；
- 长会话 id / 长任务在 264px 左右宽的窄面板里 `overflow-wrap: anywhere`，不会被裁掉；
- 打开详情时用 `scrollIntoView({ block: 'nearest' })` 把详情头部带进视野，避免从长列表
  底部打开时停在详情中段；
- 轮询继续更新当前详情；选中的会话从列表里消失（例如被移除）时自动回到列表；面板关闭后
  重新打开回到列表。

没有成员对话时整区仍然不渲染，桌面端的列表、分组、折叠、阶段/预算头部都不变。

## 为什么不用 `getContainer={false}`

`getContainer={false}` 能把 Modal 的 DOM 放进当前组件，但 Modal 的浮层依赖
`position: fixed`；面板本身是带 `overflow-y: auto` 和 `max-height` 的浮层，fixed 定位会被
面板的滚动容器裁剪或按它重新定位。内联详情不依赖任何浮层，直接复用面板的滚动，行为最稳定。

## 验证

- 真实 hub + Chrome 手机仿真（390×844）：打开「后端开发1」详情，在对话框内做一次上滑，
  修复前 `.ant-modal` 与 `.dsh-mesh-members` 同时消失（复现）；说明命中浮层的
  `pointerdown` 关闭规则。
- 用同一个「面板外 pointerdown 就关闭」规则的沙盒页面挂载本组件：详情在面板 DOM 内，
  没有 `.ant-modal`；在详情内上滑，面板 `scrollTop` 从 8 到 340，面板未关闭、详情仍在；
  在面板外按下仍然会关闭面板（规则本身没被绕过）。

## 边界

`pointerdown` 判定属于 DSH 浮层，插件不能改；以后在会话面板里再加入交互内容，也必须渲染在
面板 DOM 内，不要 portal 到 `document.body`，否则同样会在第一次触摸时被当成「点击面板外」。
