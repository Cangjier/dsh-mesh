# Step 036 成员上下文阶段优先与 call_member 预算

Step 033/035 把产品阶段、参与度和标准身份接进了成员上下文，但快照仍沿用老的
「成员状态板」结构：首行是「跟踪 N 个成员会话，其中 M 个进行中」，每个成员一行带
`进行中/空闲/异常中止` 和轮次，产品阶段块里的未参与成员也带状态。主对话因此更容易
盯着「谁在跑」而不是「这个阶段该收口了」。这次把成员上下文改成**阶段优先**：

- 移除成员对话的状态提示与成员明细行（身份、工作区、会话 id、工作范围、备注、成员压缩阈值都不再逐行出现；状态仍可由 `status_member` 查询）；
- 快照第一行给全 A/B/C/D 四个大阶段的定义；
- 每个大阶段单独设置 `call_member` 预算；没有设置时默认为该阶段参与成员数量的两倍。
  成员每把一条回复返回主对话消耗一次；预算用尽时快照强调必须进入下一个阶段并更新状态。

## 快照结构

`formatMemberStatusSnapshot` 现在固定按这个顺序拼：

```text
[产品阶段定义] 产品按 A → B → C → D → A 循环：
- A 计划与目标：所有成员参与并提出建议，最后由主对话决定本轮计划与目标。
- B 开发与测试：开发、测试、研究员参与；本轮开发的功能没有 BUG（疑难杂症除外）。
- C 产品经理使用：产品经理真实使用；发现问题回到 B 阶段，直到产品经理放行。
- D 业务介入：业务人员开展业务工作；发现问题回到 C 阶段，业务放行后回到 A 阶段并升产品版本。
[产品阶段] 20261126.1 · A 阶段（第 2 轮迭代）· 计划与目标
- call_member 预算（A 阶段）：本轮已用 2/4，剩余 2（默认 = 参与成员数 × 2）
- 阶段要求：…
- 产品目标：…
- 本轮参与：1/2（开发 c1）
- 未参与：测试 c2
后续可能走向：
1. 如果…，则 set_product_stage({ … })
- 身份：网关（自身，会话 <selfId>）；工作范围：成员发现；保持目标：关闭（只对主对话生效）；避免耗时：关闭（只对主对话生效）；call_member 预算：A 默认 / B 默认 / C 默认 / D 默认（只对主对话生效，每个大阶段单独计；未设置按参与成员数 × 2）；压缩阈值：35%
```

- **大阶段定义永远排在最前**，没有产品阶段时也一样；没有成员会话时不会再注入，
  所以不会单独产生一条只有定义的快照。
- 产品阶段块紧随定义，顺序是版本/阶段/轮次、预算、阶段要求、三个目标、本轮参与度、
  后续可能走向；只更新目标时本轮开始时间不移动，参与度和预算都不清零。
- 自身行在末尾增加 `call_member 预算`；快照**不再逐行列出成员会话**（身份、工作区、会话 id、
  工作范围、备注、成员压缩阈值都不出现），成员的身份/范围/状态统一由 `status_member` 回答。
- 成员会话缺身份/工作范围的聚合提示也不再放进快照，仍保留在 `status_member` 的结果里；自身缺
  身份/范围的提示继续保留。
- `formatProductStageParticipation` 新增 `statuses` 选项：成员上下文传 `false`，未参与
  成员只列名称/角色，不显示 `（异常中止，需先恢复会话）`；`set_product_stage` 的工具
  结果和前进被拒的说明仍保留状态，方便解释为什么需要先恢复会话。
- 成员状态仍然完整存在于 `status_member`、`wait_member`/`call_member` 的返回和 Web
  面板里；这次只改成员上下文。

## call_member 预算

### 设置

`set_member_scope` 的 `callMemberBudget`（别名 `call_member_budget`）是**按大阶段**的对象，
可以只给要设的阶段，每个阶段取整数 1–999：

```text
set_member_scope { "callMemberBudget": { "A": 26 } }
set_member_scope { "callMemberBudget": { "B": 6, "C": 2, "D": 2 } }
set_member_scope { "conversationId": "self", "call_member_budget": { "A": 26 } }
```

- **只对自身/主对话生效**；设置成员会话时忽略，返回文字会说明；
- **没有统一设置**：传一个数字会报错，必须按 A/B/C/D 分别给；
- 每个阶段独立合并：先设 A、再设 B 不会清掉 A；
- 与 `identity`/`role`/`scope`/`note`/`keep`/`keepPrompt`/`avoidLongJobs`/`compressPercent`
  一起保存在同一个会话记录里（`member-scopes.json`）；
- 没有设置的阶段没有“不限制”：运行时默认 **该阶段参与成员数量 × 2**（还没有参与成员时
  按 1 计）。参与成员数按当前阶段要求的会话算：A 阶段是所有跟踪的会话，B 是开发/测试/
  研究员，C 是产品经理，D 是业务；成员会话增加或减少后，默认值随之下一次快照重新计算；
- 自身行显示 `A 26 / B 默认 / C 默认 / D 默认`；快照预算行标 `已设置` 或
  `默认 = 参与成员数 × 2`。

### 消耗与重置

- 判断标准是**成员对话的回复返回到主对话**：`wait_member` 取走回复和兜底投递共用
  同一张 `task.replies` 回复表，回复被接受一次就计一次；不是按 `call_member` 派发次数
  计，也不是按成员会话个数计。
- 只统计当前阶段轮次开始（`roundStartedAt`，旧状态回退到 `updatedAt`）之后接受的回复；
  本轮开始前的回复不计。
- 换阶段、开新一轮（`round` 变化，含 D→A）都会重置 `roundStartedAt`，预算随之从头计；
  只更新目标不会重置。
- 只统计本对话（`originSessionId`）跟踪的成员会话的回复，其他主对话的回复不计。
- 预算用尽后仍允许 `call_member`（软约束）：快照会反复强调，但不会拒绝调用。

### 用尽时的提示

`formatCallMemberBudget` 在 `已用 >= 预算` 时追加一段强调：

```text
[call_member 预算用尽] A 阶段本轮预算 26 次已用完（已有 26 条成员回复返回主对话）。
不要再派新任务：必须进入下一个阶段，并用 set_product_stage 及时更新阶段和目标状态；
本轮参与未齐时，先 wait_member 取回已派任务的回复。
```

它不绕开 Step 033 的前进门槛：参与度没齐时 `set_product_stage` 仍会被拒绝。预算用尽
时先确认回复都已收齐，再进入下一阶段；本轮参与未齐时先 `wait_member` 取回已派任务的
回复。
