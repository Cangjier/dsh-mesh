# Step 046 业务参与 B 阶段试用

B 阶段原来只有开发、测试、研究员和产品经理参与，业务人员到 D 阶段才介入。这样业务对
产品的意见往往到交付前才出现，下一轮 A 阶段定目标时也缺少真实试用反馈。现在 **B 阶段
也要求业务人员参与**，任务固定为：试用**上一个部署版本**（当前线上版本，不是本轮还在开发的代码），
提出问题或需求，为下一轮 A 阶段做准备。

## 改动

- `stageRequiredRoles('B')` 从 `开发/测试/研究员/产品经理` 变为
  `开发/测试/研究员/产品经理/业务`；
- `PRODUCT_STAGE_REQUIREMENTS.B` 增加业务职责：
  「开发、测试、研究员、产品经理、业务参与；本轮开发的功能没有 BUG（疑难杂症除外）；
  产品经理调研竞品功能、与自家产品对比并输出报告，业务人员试用上一个部署版本（当前线上版本）
  并提出问题或需求，为下一轮 A 阶段做准备。」
- 四阶段定义首行、成员上下文 `- 阶段要求：…`、`set_product_stage` 工具描述同步更新。

## 连带行为

- **参与度门槛**：B 阶段换到 C 或开启新 `round` 前，业务人员的成员会话也必须已参与本轮，
  否则 `set_product_stage` 返回 `ok:false`，状态不变，并列出「没有业务身份的成员会话」。
- **放行检查**：离开 B 时若没有业务身份的成员会话，`[放行检查]` 会点名。
- **默认预算**：B 阶段没设 `callMemberBudget` 时，默认值 = 本轮参与成员数 × 2，现在把
  业务会话也算进去。
- 业务人员同时仍是 D 阶段角色：B 的试用反馈正好成为下一轮 A 阶段定目标和 D 阶段验收的输入。

## 不变

- 没有新增工具参数或存储字段；`set_member_scope { "role": "业务" }` 的用法不变。
- A 阶段仍要求所有已跟踪成员参与；C 只要求产品经理，D 只要求业务。
- 已有阶段状态不需要迁移；下一次 `set_product_stage` 按新的角色要求校验。

## 验证

- `test/product-stage.test.mjs`：B 角色列表、参与度、前进门槛、放行检查、阶段定义文本。
- `test/member-context.test.mjs`：快照缺标准身份时列出业务。
- `npm test` 全通过；`npm run typecheck` 通过。
