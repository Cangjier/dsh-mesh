# Step 045 产品经理参与 B 阶段竞品调研

B 阶段原来只要求开发、测试、研究员参与；产品经理到 C 阶段才真正使用产品。这样到
下一轮 A 阶段定目标时，竞品信息往往临时补，缺少和自家产品的系统对比。现在 **B 阶段也要求
产品经理参与**，任务固定为：调研竞品功能、与自家产品逐项比较、输出报告，为下一轮 A 阶段
做准备。

## 改动

- `stageRequiredRoles('B')` 从 `开发/测试/研究员` 变为 `开发/测试/研究员/产品经理`；
- `PRODUCT_STAGE_REQUIREMENTS.B` 写清产品经理在 B 的交付物：
  「开发、测试、研究员、产品经理参与；本轮开发的功能没有 BUG（疑难杂症除外）；
  产品经理调研竞品功能、与自家产品对比并输出报告，为下一轮 A 阶段做准备。」
- 四阶段定义首行、成员上下文 `- 阶段要求：…`、`set_product_stage` 工具描述同步更新。

## 连带行为

- **参与度门槛**：B 阶段换到 C 或开启新 `round` 前，产品经理的成员会话必须已参与本轮
  （回复被 `wait_member` 取走或兜底投递），否则 `set_product_stage` 返回 `ok:false`，
  状态不变，并列出「没有产品经理身份的成员会话」。
- **放行检查**：离开 B 时若没有产品经理身份的成员会话，`[放行检查]` 会点名。
- **默认预算**：B 阶段没设 `callMemberBudget` 时，默认值 = 本轮参与成员数 × 2，现在把
  产品经理会话也算进去（多一个产品经理就多两次默认预算）。
- 产品经理同时仍是 C 阶段角色：B 的调研报告正好成为 C 阶段试用和下一轮 A 的输入。

## 不变

- 没有新增工具参数或存储字段；`set_member_scope { "role": "产品经理" }` 的用法不变。
- A 阶段仍要求所有已跟踪成员参与；C / D 的角色要求不变。
- 已有阶段状态不需要迁移；下一次 `set_product_stage` 按新的角色要求校验。

## 验证

- `test/product-stage.test.mjs`：B 角色列表、参与度、前进门槛、放行检查、阶段定义文本。
- `test/member-context.test.mjs`：快照缺标准身份时列出产品经理。
- `npm test` 全通过；`npm run typecheck` 通过。
